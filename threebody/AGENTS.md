# AGENTS.md — Earth–Moon Three-Body Sandbox

## Purpose

This project is an interactive Earth–Moon Circular Restricted Three-Body Problem (CR3BP) simulator.

The spacecraft is a massless test particle moving under the gravity of the Earth and Moon in the standard circular restricted three-body model. The product exists to let a user *play with real nonlinear orbital dynamics* — L1–L5, zero-velocity curves, tadpoles, horseshoes, unstable collinear equilibria, targeting burns and eventually halo/NRHO/manifold dynamics.

Static GitHub Pages. No backend is required.

## Hard rule: no fake trajectories

Every spacecraft path shown as a physical trajectory must come from numerical integration of the CR3BP equations or from a numerically corrected periodic/transfer solution that is then propagated by the same equations.

Forbidden:

- Bézier curves as orbit paths
- splines that visually imitate horseshoes/halos/transfers
- directly moving position toward L1–L5
- hand-authored “turnaround” behavior near the Moon
- different fake trajectories for rotating and inertial views

Interpolation is allowed only for rendering between already integrated states.

## Canonical dynamics

Use normalized Earth–Moon CR3BP coordinates unless a clearly isolated conversion layer is being used.

```text
mu ≈ 0.0121505856
Earth = (-mu, 0, 0)
Moon  = (1-mu, 0, 0)

r1 = sqrt((x+mu)^2 + y^2 + z^2)
r2 = sqrt((x-1+mu)^2 + y^2 + z^2)

Omega = 0.5*(x*x+y*y) + (1-mu)/r1 + mu/r2

xddot =  2*ydot + dOmega/dx
yddot = -2*xdot + dOmega/dy
zddot =             dOmega/dz

C = 2*Omega - (xdot^2 + ydot^2 + zdot^2)
```

Do not change sign/frame conventions casually. Any change requires explicit cross-validation against known Lagrange-point locations and Jacobi invariance.

## Numerical accuracy contract

Physics fidelity is a release requirement.

### Integrator

- Use adaptive high-order integration for trajectory generation.
- Dormand–Prince RK5(4) is acceptable for the first implementation if it passes invariant/convergence tests.
- Long horseshoe orbits must be tested for secular Jacobi drift. Upgrade the method if necessary.
- Long propagation should run in a Web Worker where practical.

### Invariant monitoring

For unforced propagation, measure Jacobi drift continuously.

Do not hide numerical error by renormalizing the state or Jacobi constant.

The diagnostics must be able to report:

```text
C0
Cnow
absolute drift
relative drift
integrator steps
rejected steps (if adaptive)
```

### Convergence

A preset is not “validated” until re-integrating it with tighter tolerance produces the same qualitative orbit and sufficiently close state history.

## Lagrange points

Compute L1–L5 from the model.

Do not treat all L points as equivalent destinations.

- L1/L2/L3 are unstable collinear equilibria.
- L4/L5 are triangular equilibria and admit stable tadpole motion in the ideal Earth–Moon CR3BP.

If the UI says “Go to L1,” the implementation must distinguish among:

- fly through L1,
- target the equilibrium point as an educational unstable solution,
- enter an L1 Lyapunov orbit,
- later: halo/Lissajous/manifold options.

---

## Horseshoe requirement

A horseshoe preset is a first-class acceptance target.

It must be:

- generated by CR3BP integration,
- characteristic in the rotating frame,
- continuous around the L3/L4/L5 region,
- naturally reversed by the dynamics,
- collision-free over the displayed interval,
- numerically stable enough to pass the Jacobi-drift criterion.

Do not call any wide curved orbit a horseshoe simply because it resembles a U-shape.

---

## Co-orbital classification

Use dynamical definitions, not shape labels.

In an appropriate 1:1 resonant description:

- tadpole: resonant angle librates about L4 or L5 (~±60°),
- horseshoe: librates about 180° and encompasses both triangular regions,
- quasi-satellite: librates about 0°.

The rotating-frame plot is a visualization; the classification comes from the dynamics.

---

## Zero-velocity curves

Zero-velocity curves are derived from the spacecraft Jacobi constant:

```text
2*Omega(x,y) = C
```

Forbidden regions are regions where `2*Omega < C` because the implied squared speed would be negative.

The curve must update after an impulsive burn changes the spacecraft velocity and therefore changes C.

Do not draw decorative contour shapes detached from the current Jacobi constant.

---

## Burns and targeting

A burn is an instantaneous velocity change in the current reference state.

After a burn:

- position is unchanged,
- velocity changes by Δv,
- Jacobi constant changes accordingly,
- subsequent motion is ballistic unless another burn is commanded.

Destination planning must use numerical shooting/correction. Never steer the spacecraft position toward a point during ballistic propagation.

A planned transfer must expose:

- Δv,
- time of flight,
- terminal residual/miss distance,
- target condition,
- pre/post burn Jacobi constant.

Do not advertise “minimum Δv” without an actual optimization.

---

## Reference-frame contract

Support both:

1. rotating/synodic frame,
2. inertial barycentric frame.

They must show the same physical trajectory transformed between coordinate systems.

The rotating frame keeps Earth, Moon and L points fixed. The inertial frame rotates those same states at the system angular rate.

Do not integrate a second trajectory just to make the inertial picture look nicer.

---

## Presets

Presets are reproducible initial states, not animations.

Initial required preset families:

- L4 tadpole
- L5 tadpole
- Earth–Moon horseshoe
- L1 unstable equilibrium demonstration
- L2 unstable equilibrium demonstration
- free/chaotic launch example

Later:

- planar Lyapunov families
- quasi-satellite-like examples where physically applicable
- DRO
- 3D halo
- Lissajous
- NRHO
- invariant-manifold transfers

Every preset should store model state and propagation settings sufficient to reproduce it.

---

## Visualization principles

The orbit should be understandable, not merely pretty.

Recommended overlays:

- Earth
- Moon
- barycenter
- L1–L5
- spacecraft
- propagated trail
- velocity vector
- planned Δv vector
- zero-velocity curves
- optional effective-potential contours
- time scale
- current frame
- Jacobi constant/drift

Visual scale may be nonliteral for Earth/Moon radii so they remain visible, but orbital distances and dynamics must remain physically scaled. Any enlarged body radius used only for display must not change collision/gravity calculations.

---

## Collision and close-approach handling

Use physical body radii for collision checks in dimensionalized space or equivalent normalized radii.

Do not bounce the spacecraft off Earth/Moon unless a clearly labeled nonphysical sandbox mode is added later.

Default behavior on impact: mark trajectory as collision and stop propagation.

Close approaches should trigger smaller integrator steps through the adaptive error controller, not a hand-coded path correction.

---

## Performance philosophy

Never reduce numerical correctness to gain animation FPS without measurement.

Trajectory calculation and screen rendering are separate workloads:

- integrate accurate states asynchronously,
- cache trajectory samples,
- render/play them smoothly,
- recompute only when initial state, burn, target or model parameters change.

The user does not need the ODE solver itself to run at display refresh rate.

## Acceptance invariants

A build is unacceptable if any are false:

1. Earth and Moon remain fixed in the rotating frame.
2. L1–L5 are solved from the CR3BP model and agree with known Earth–Moon locations.
3. A free spacecraft follows direct CR3BP integration.
4. Jacobi constant remains within the established numerical error budget without burns.
5. A burn changes velocity and Jacobi constant but not position instantaneously.
6. Zero-velocity curves correspond to the current C.
7. Rotating and inertial views are transforms of the same trajectory.
8. L1/L2/L3 instability can be demonstrated by a small perturbation.
9. L4/L5 tadpole presets arise from integration, not drawing.
10. Horseshoe preset arises from integration and exhibits genuine co-orbital horseshoe behavior.
11. Tightening integrator tolerance does not materially change validated presets.
12. A collision with Earth or Moon is detected physically rather than visually.
13. Targeted paths report residual error and do not silently snap to the destination.
14. No orbit family is labeled solely by visual resemblance.

## v0.1 boundary

Start planar. Do not rush into halo/NRHO before the 2D solver is trustworthy.

v0.1 should prove:

- accurate Earth–Moon planar CR3BP,
- L1–L5,
- rotating/inertial frame switching,
- Jacobi/zero-velocity geometry,
- free burns,
- target planning,
- tadpoles,
- a real horseshoe orbit.

The strange paths are the product. Do not fake the strange paths.
